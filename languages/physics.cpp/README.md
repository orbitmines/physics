## Installation

```bash

```

C++20 (GCC 11, Clang 14, MSVC 19.30 or later) and CMake 3.16. With vcpkg or Conan it is `orbitmines-physics`; from CMake directly:

```cmake
include(FetchContent)
FetchContent_Declare(orbitmines_physics GIT_REPOSITORY https://github.com/orbitmines/physics GIT_TAG main SOURCE_SUBDIR languages/physics.cpp)

target_link_libraries(your_target PRIVATE orbitmines::physics)
```

or, once installed, `find_package(orbitmines-physics CONFIG REQUIRED)` and the same `orbitmines::physics`.

## Using it

C++ has no dynamic members, so a Ray object is reached by name: `get(x, "name")`, `call(x, "method", {args...})`, `set(x, "name", value)`, `make("Class", {kw("field", value), ...})`, and a class or a theory is `K("Name")`. Every value is a `Value`: numbers are `double`, lists hold `Value`s, `str(x)` writes one as text.

```cpp
#include <orbitmines/physics.hpp>
using namespace orbitmines::physics;

// a theory, and its continuous model on the CPU: a box of cells, the vacuum settled, one body in it
Value medium = call(K("G"), "medium", {31.0, 96.0, 3.0, 8.0, 1.0});
set(medium, "local_rays", true);
call(medium, "add", {make("Hole", {kw("x", 15.0), kw("y", 15.0), kw("mx", 0.3), kw("ways", 1.0)})});
get(medium, "seed");
for (int t = 0; t < 5; t++) get(medium, "tick");
```

## A simulation of sources: the plan

A run is set by a `Plan`: how many sources, how big a box, and four kinds of setting - `Resolution` (how finely the medium reads), `Budget` (how much of the device it may take), `Batching` (how a run larger than the device is carried) and `Output` (what comes back). The plan says what the device must hold before anything runs.

```cpp
Value plan = make("Plan", {kw("sources", 1e9), kw("side", 241.0)});
set(get(plan, "budget"), "compact", true);   // twelve bytes a source
std::printf("%s\n", str(call(plan, "report", {16.0 * (1LL << 30), (double) (1LL << 31)})).c_str());
```
