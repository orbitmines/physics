# @orbitmines/physics - TypeScript

The physics library in TypeScript: the theories and their rules, the continuous model derived from them (the medium), and the runtime that carries a simulation of sources - stars, planets, any bodies a theory has - on the GPU. Back to the [project README](../../README.md).

## Installation

```bash
# JavaScript/TypeScript
npm install @orbitmines/physics
```

The package is TypeScript source (`"type": "module"`); run it with Deno, `tsx`, or any runtime that loads `.ts`. On the GPU it uses WebGPU (`navigator.gpu`: Deno with `--unstable-webgpu`, or a browser).

## Using it

```ts
import * as physics from "@orbitmines/physics";

// a theory, and its continuous model on the CPU: a box of cells, the vacuum settled, one body in it
const medium = physics.G.medium(31, 96, 3, 8, 1);
medium.local_rays = true;
medium.add(new physics.Hole({ x: 15, y: 15, mx: 0.3, ways: 1 }));
medium.seed;
for (let t = 0; t < 5; t++) medium.tick;
```

## A simulation of sources on the GPU

A run is set by a `Plan`: how many sources, how big a box, and four kinds of setting - `Resolution` (how finely the medium reads), `Budget` (how much of the device it may take), `Batching` (how a run larger than the device is carried) and `Output` (what comes back). The plan says what the device must hold before anything runs.

```ts
import * as physics from "@orbitmines/physics";

const plan = new physics.Plan({ sources: 1e6, side: 241 });
plan.budget.compact = true;           // twelve bytes a source; sources made and counted on the device
console.log(plan.report(16 * 2 ** 30, 2 ** 31));

/* the box is the view and a margin round it (plan.resolution.margin c-bars), run and never drawn */
const mid = (plan.box_side - 1) / 2, view = (plan.side - 1) / 2;
const run = await physics.webgpu.medium(plan.box_side, 96, 3, 1, physics.G, 8, physics.G.lattice.D, { apart: plan.sources, local: true, paced: true, plan });
await run.generate({ count: plan.sources, mass: 1.7 / plan.sources, shape: "disc", centre: [mid, mid], scale: 24, seed: 1 });
run.seed();
await run.stand();                    // the field stands before anything moves
await run.launch({ centre: [mid, mid], sigma: 0.2 });
for (let t = 0; t < 1000; t++) await run.tick();
const counts = await run.grid({ grid: 256, centre: [mid, mid], span: view });
console.log(`${await run.departed() / 1.7} of the mass has left the box`);
```

## Settings

| Setting | Default | What it trades |
|---|---|---|
| `resolution.cells` | 3 | cells to a c-bar: resolution against every per-cell cost |
| `resolution.ways` | 96 | directions a point tells apart |
| `resolution.keeps` | 4 | bundles a direction keeps before merging |
| `resolution.list`, `near_list`, `near_cells` | 12, 96, 5 | the kernels' own lists and the exact-reading radius |
| `resolution.cell_pull` | true | sources sharing a cell read as the cell, once |
| `resolution.margin` | 2 | c-bars of box run round the view and never drawn: the box's own edge kept out of sight |
| `resolution.speed` | 0.25 | the fastest a compact source is kept at (c-bar a tick) |
| `budget.memory`, `binding` | the device's | what the run may hold, and one binding |
| `budget.aim_ms`, `longest_ms`, `duty`, `in_flight` | 15, 250, 0.5, 2 | how the device is paced, so it still draws the screen |
| `budget.compact` | false | sources in twelve bytes each, made and counted on the device |
| `batching.tiles`, `ticks` | 1, 1 | a box larger than the device, carried a tile at a time (planned) |
| `output.every`, `grid`, `sources` | 0, 128, false | frames, their grid, and whether sources come back |
